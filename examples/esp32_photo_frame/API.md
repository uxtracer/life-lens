# life_lens 智能相框接口说明书

> 给单片机/固件开发者的对接文档。读完这份就够写固件了,**不需要看服务端源码**。

---

## 1. 这是什么

`life_lens` 是跑在一台电脑上的相册服务。它对局域网开放了一组**只读取图接口**,给各类智能相框/带屏设备做照片轮播用(接口是通用 HTTP,与具体硬件无关):

- 设备每隔几秒发一个 HTTP GET,服务端**直接返回一张已经缩放好的 JPEG**(尺寸由你指定),解码铺屏即可。
- "放哪张照片"由服务端决定(收藏照片 / 指定主题,内部已做轮播洗牌),设备不用管选片逻辑。
- 也提供"播放列表"接口,给想自己管播放顺序的设备。

**传输只在局域网内,不经过公网。**

---

## 2. 前置条件(对方电脑上要做的)

1. life_lens 服务已启动,默认监听 `0.0.0.0:7878`。
2. 在 life_lens 配置页打开「🖼️ 智能相框」开关(默认是关的)。**没开 → 所有接口返回 403。**
3. 拿到那台电脑的**局域网 IP**(配置页相框卡片里会显示,形如 `192.168.1.100`)。

> 设备和服务器必须在**同一个 Wi-Fi / 局域网**。本机 `127.0.0.1` 是全功能,但单片机走的是局域网 IP。

---

## 3. 基本信息

| 项 | 值 |
|---|---|
| 协议 | HTTP/1.1(明文,无 TLS) |
| 主机 | 服务器局域网 IP,如 `192.168.1.100` |
| 端口 | `7878`(默认) |
| 鉴权 | 无口令。靠"开关 + 来源是局域网"放行(见前置条件) |
| 基址 | `http://<IP>:7878` |

所有接口都是 **GET**。下面路径都基于基址。

---

## 4. 接口清单

### 4.1 `GET /api/frame/next` —— 主接口:取轮播下一张

一次请求直接返回一张 JPEG。这是固件最常用的接口:**循环调用它即可实现轮播**。

**查询参数**(都可选):

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `w` | int | 1024 | 目标宽(像素)。范围 16–2048。**务必传你屏幕的真实宽度**,否则默认给 1024(偏大费内存) |
| `h` | int | 1024 | 目标高(像素)。范围 16–2048。**务必传你屏幕的真实高度** |
| `mode` | string | `contain` | `contain`=等比缩放放进 w×h(可能留边,不裁);`cover`=等比缩放并裁剪铺满 w×h |
| `quality` | int | 90 | JPEG 质量,范围 40–95。从原图单次压缩;越小图越小越省内存/带宽 |
| `theme` | string | (服务端配置) | 临时指定主题;一般**不传**,用服务端配置页设的主题 |

**响应**:

- 状态 `200`,`Content-Type: image/jpeg`,body 就是 JPEG 字节(**基线 baseline JPEG**,可直接喂 TJpg_Decoder 之类的解码器)。
- 响应头里带元信息(可选读取,用于显示标题):

| 响应头 | 说明 |
|---|---|
| `X-Photo-Id` | 照片唯一 id(字符串) |
| `X-Photo-Date` | 拍摄时间,ISO8601,如 `2025-08-07T12:15:54Z`(可能没有) |
| `X-Photo-Caption` | AI 生成的描述。**经过 URL(百分号)编码的 UTF-8**,要显示中文需先 percent-decode(可能没有) |
| `Cache-Control` | `no-store`(每次都给新的一张) |

**示例**:
```
GET http://192.168.1.100:7878/api/frame/next?w=800&h=480&mode=cover
→ 200 OK
  Content-Type: image/jpeg
  X-Photo-Id: AAAAAAAA-1111-2222-3333-444444444444
  X-Photo-Date: 2026-01-01T15:35:29Z
  X-Photo-Caption: %E6%B5%B7%E8%BE%B9%E7%9A%84%E5%90%88%E5%BD%B1
  <JPEG 二进制...>
```

curl 测试:
```bash
curl -v "http://192.168.1.100:7878/api/frame/next?w=800&h=480&mode=cover" -o photo.jpg
```

---

### 4.2 `GET /api/frame/photo/{photo_id}` —— 取指定照片

按 id 取某一张,参数同 `/next` 的 `w/h/mode/quality`。给"自己管播放列表"的设备配合 `/playlist` 用。

```
GET http://192.168.1.100:7878/api/frame/photo/AAAAAAAA-1111-2222-3333-444444444444?w=800&h=480&mode=cover
→ 200 image/jpeg(同上,带 X-Photo-* 头)
→ 404 如果 id 不存在或该照片没缓存
```

---

### 4.3 `GET /api/frame/playlist` —— 取播放列表(JSON)

返回当前主题下一批照片的 id + 描述。设备可以缓存这个列表,自己控制轮播顺序与节奏,再用 `4.2` 逐张取图。

**查询参数**:`theme`(可选)、`limit`(默认 200,最大 1000)。

**响应** `200 application/json`:
```json
{
  "theme": "海边",
  "count": 71,
  "items": [
    { "photo_id": "BBBBBBBB-5555-6666-7777-888888888888",
      "date": "2025-08-07T12:15:54Z",
      "caption": "两人站在护栏前,背景是水域和山丘" },
    { "photo_id": "…", "date": "…", "caption": "…" }
  ]
}
```
> 列表只含有缓存、能直接取图的照片。`caption` 是原文(未编码)。

---

### 4.4 `GET /api/frame/info` —— 查当前状态(JSON)

调试用。返回当前主题和照片池大小。

```
GET http://192.168.1.100:7878/api/frame/info
→ 200 { "theme": "", "pool_size": 1000, "kind": "favorites", "using_favorites": true }
```
`kind`:`favorites`(收藏)/ `person`(主题是人名,按人脸)/ `theme`(主题是场景/物品,按内容)。

## 5. 错误码

| 状态码 | 含义 | 固件该怎么办 |
|---|---|---|
| `200` | 正常 | 解码显示 |
| `403` | 相框开关没开 / 不是局域网来源 | 屏幕提示"请在电脑上打开智能相框开关",稍后重试 |
| `404` | 照片池为空(没有收藏 / 主题没匹配到),或指定 id 不存在 | 提示"没有可显示的照片",稍后重试 |
| 连接超时/失败 | 网络不通 / 服务没起 | 重连 Wi-Fi,重试 |

错误响应体是 JSON,如 `{"detail":"内网访问未开启(在本机配置页打开「内网访问」开关)"}`,固件可不解析,按状态码处理即可。

## 6. 推荐固件流程

### 方案 A:傻瓜轮播(推荐,最省事)

```
初始化屏幕、连 Wi-Fi
循环:
    GET /api/frame/next?w=<屏宽>&h=<屏高>&mode=cover
    if 200:
        把 body 整段读进内存
        JPEG 解码 → 铺满屏幕
        (可选)读 X-Photo-Caption,percent-decode 后叠字幕
    else:
        屏幕显示对应错误提示
    sleep N 秒(如 30s)
```
服务端已经把图缩放到 `w×h`,单片机**不用自己缩放**,内存压力小。

### 方案 B:本地管列表(需要更强控制时)

```
启动时 / 每隔几十分钟:GET /api/frame/playlist → 缓存 photo_id 列表
循环:
    从列表里取下一个 id(自己决定顺序/随机)
    GET /api/frame/photo/{id}?w=<屏宽>&h=<屏高>&mode=cover → 解码显示
    sleep N 秒
```

## 7. 给固件开发的注意事项

- **图已是 baseline JPEG**,常见的 JPEG 解码库(如 TJpg_Decoder)能直接解。
- **尺寸传你屏幕的真实分辨率**(如 800×480)。别传过大,单张 JPEG 越小越稳;内存吃紧就把 `quality` 调到 60–70。
- **从原图出图,单次压缩**:服务端直接从全分辨率原图缩到你要的尺寸再编码一次(不是在压过的小图上二次压缩),请求 ≤2048 都清晰。仅当原图不在本机(如照片只在 iCloud 没下载)才回退到 1024px 副本。
- **`mode=cover`** 适合全屏相框(裁剪铺满);**`mode=contain`** 不裁、可能留边。
- **响应头 `X-Photo-Caption` 是 URL 编码的**:HTTP 头只能放 ASCII,中文被百分号编码了,要显示得先解码;不显示字幕就忽略这个头。
- **每次 `/next` 都是新的一张**(响应头 `Cache-Control: no-store`),不用加防缓存参数。
- **超时**建议:连接 5s、读 body 10s;失败就重试,别卡死。
- 一台服务器可同时被多个相框访问,互不影响。

## 8. 一眼速查

```
基址:  http://<服务器局域网IP>:7878

GET /api/frame/next?w=800&h=480&mode=cover     → JPEG(轮播下一张,主接口)
GET /api/frame/photo/{id}?w=800&h=480          → JPEG(指定照片)
GET /api/frame/playlist?limit=200              → JSON(id 列表)
GET /api/frame/info                            → JSON(状态调试)

响应头:X-Photo-Id / X-Photo-Date / X-Photo-Caption(URL编码)
错误:  403=开关没开  404=没照片  其它=网络问题
前提:  电脑上把「智能相框」开关打开,设备和电脑同一 Wi-Fi
```
